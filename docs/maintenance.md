# JUNA 网站设计与维护说明

## 内容边界

网站讲述公开科学任务与已发表成果。论文区明确为精选目录。新增内容应优先使用 CJPL、参与机构、期刊发表版本和合作组公开资料。不得以未公开结果、预印本或私人信息充当已发表成果；预印本如收录，须标明状态。

每次更新记录原始来源及核验日期。当前主要核验日期：2026-10-04。

- 岩层覆盖约 2400 m，指覆盖厚度，不是隧道长度。
- 400 kV 为终端电压；能量增益为 qΔV。数值须注明实验室系或质心系。
- 不将旧 Run-1 的位置、束流或靶配置自动写成当前运行配置。
- ¹²C(α,γ)¹⁶O 与三 α 过程共同影响碳氧丰度。只描述已公开目标和可核验结果。
- ¹³C(α,n)¹⁶O 的公开 2022 数据几乎完整覆盖 i 过程窗口，不泛化为所有窗口均完整覆盖。
- ¹⁹F(p,αγ)¹⁶O 的 γ 探测对应氧激发态分支；¹⁹F(p,γ)²⁰Ne 是另一通道。
- 镁反应的俘获 γ 与 ²⁶Al 基态衰变产生的星际 1.809 MeV γ 来源不同。基态和同核异构态需分别处理。
- 原论文正式年份、在线日期、卷页信息分别保留。例如 ²⁵Mg 首篇论文在线 2021、正式卷年 2022。

## 数据字段

`Reaction` 包含 `id`、`formula`、双语 `tag/title/text/task/type`、`input/product/particle/tone`、双语 `publicProgress/detector` 和论文 `references`（slug）。关联至少一个论文或综述；研究目标不写成已完成成果。

`Paper` 包含稳定 `slug`、`reactionId`、`kind`、`language`、`authors`、正式 `year`、`publishedOnline`、`journal/volume/pages`、`doi/url`、双语 `title/summary/detail`、原文 `englishTitle`、`citation/bibtex`。简式作者须标明 et al.；完整作者以期刊版本为准。Slug 发布后保持不变，防止旧分享链接失效。

新增论文需核对题名、作者、DOI、卷页、发表状态和科学结论，并给出对应反应；更新 `site-data.ts` 后详情路由与站点地图自动生成。图像、参数和机构角色来源保存到 `credits`；使用新照片前确认来源和授权。

合作联系当前提供相关机构公开入口。项目专用邮箱、负责人、访问流程和完整机构名单需经项目方确认后录入，不通过推测补齐。

## 视觉与交互

- 主背景 #05090f，次背景 #08111d，正文 #edf3fa，强调 #9ad5ff，次文字保持足够亮度。
- 页面依次为项目身份、深地条件、实验装置、科学研究、成果与动态、合作联系。
- 真实装置照片与星云背景承担项目和天文学视觉，不将概念图当作工程布局。
- 移动端内容宽度为视口减 40 px；360 px 以下减 32 px。文字和公式可读，卡片分为两列或单列，操作目标原则上至少 44 px。
- 首页首屏两个入口为了解实验和查看成果。研究任务关联公开进展、独立研究页与论文详情。
- 动画仅辅助阅读。尊重系统减少动态效果；可手动关闭；离屏或隐藏标签页停用循环动画；关闭后保留单步操作。
- 首页与详情共用 `juna-language` 语言偏好。查询参数可分享研究和筛选状态，浏览器前进后退恢复状态。

## 发布检查

1. 运行 `pnpm check`、`pnpm build`。脚本检查所有详情页及本地链接/资源，不发布 `dist/server`、依赖或密钥。
2. 查看首页、四个研究方向、五篇论文的直接链接，刷新详情确认未落入错误页。
3. 验证：语言切换、反应选择、四步探测、装置选择、搜索/年份/方向组合、无结果重置、复制引用/BibTeX、下载、来源对话框、系统减少动效。
4. 用 `/juna/qa/responsive.html` 检查 360、390、430 和 844 px 横屏布局；它是 noindex 的排版检查入口。检查溢出、公式、菜单和点击目标。另需条件允许时做真实设备体验。
5. 检查页首图片加载、控制台应用错误、内部链接、404 返回首页和分享元数据。
6. 推送 `website` 源码及 `gh-pages` 静态文件。等待 Pages 构建成功，再检查线上内容。发布时保留前两次发布的 `_next/static/` 哈希资源，避免浏览器缓存旧 HTML 后加载失效。`prepare-pages.mjs` 会保留本地前次 `out/` 的静态资源；全新检出时应从部署分支保留这些文件。待缓存窗口结束后可单独清理，不在同一次上线中删除旧资源。
7. 回滚：将上一部署提交的树作为新提交发布到 `gh-pages`；不重写历史。保留对应源码提交。

性能目标为真实用户 75 分位 LCP ≤ 2.5 s、INP ≤ 200 ms、CLS ≤ 0.1。发布前的资源与排版检查不能替代真实用户性能数据；未测量时不声明已达标。
